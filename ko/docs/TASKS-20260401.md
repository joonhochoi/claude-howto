## 1단계 — 인프라와 취약 모듈 (2026년 4월)

**목표 마일스톤: M1**

### 기둥 4: 신규 사용자 온보딩

- [ ] **T-001** — `scripts/quickstart.sh` 작성
  - `~/.claude/` 디렉터리를 탐지합니다(없으면 사용자 확인 후 생성).
  - 첫 슬래시 커맨드 + CLAUDE.md + 스킬을 사용자 설정으로 복사합니다.
  - AGENT-INDEX.md로 연결되는 에이전트 탐색 안내 줄을 CLAUDE.md에 추가합니다.
  - 멱등: 이미 있는 파일은 경고와 함께 건너뛰고 절대 덮어쓰지 않습니다.
  - 완료 시 다음 단계를 출력합니다.

- [ ] **T-002** — `QUICKSTART.md` 작성("첫 15분" 시각 가이드)
  - 터미널 단계를 코드 블록으로 주석 처리해 담습니다(가능하면 PNG 스크린샷 대신 ASCII 또는 Mermaid 선호).
  - 각 화면을 만들어 내는 명령을 기록해 두어 다시 캡처할 수 있게 합니다.

- [ ] **T-003** — 10개 모듈 README 전체에 난이도 배지 추가
  - 형식: 각 모듈 README 상단에 `> 🟢 **Beginner** | ⏱ 30 minutes`
  - 배지 아래에 "무엇을 만들게 되는지" 불릿 미리보기 추가

### 기둥 7: 살아 있는 커리큘럼

- [ ] **T-004** — `WHATS-NEW.md` 작성
  - 형식: 기능 변경별 불릿 항목과 함께 `## CC vX.X — DATE`
  - 현재 CC 버전에 대한 항목을 최소 1개 이상 추가

- [ ] **T-005** — 10개 모듈 README 전체에 버전 배지 추가
  - 형식: `> ✅ Verified against Claude Code **vX.X.X** · Last verified: YYYY-MM-DD`
  - 각 모듈 프론트매터에 `cc_version_verified` 추가

- [ ] **T-006** — `.github/workflows/staleness-check.yml` 작성
  - 스케줄: 매주 월요일 09:00 UTC
  - 프론트매터에서 각 모듈의 `last_verified` 날짜를 읽습니다(`yq` 또는 10줄짜리 Python 스크립트 사용).
  - 30일 넘게 검증되지 않은 모듈에 대해 GitHub Issue를 생성합니다.
  - 같은 제목의 열린 이슈가 이미 있으면 건너뜁니다.

### 기둥 6: 콘텐츠 품질 (CLAUDE.md)

- [ ] **T-007** — 프로젝트용 루트 `CLAUDE.md` 작성
  - 프로젝트 자체 설정을 통해 모범 사례를 보여줍니다.
  - 기여 규칙, 모듈 구조, 유지보수 워크플로를 문서화합니다.

### 기둥 2: AI 에이전트 인덱스 (생성기)

- [ ] **T-008** — `scripts/build-agent-index.py` 작성
  - 10개 모듈 README 파일을 모두 읽습니다.
  - 추출 대상: 제목(→ 주제), 코드 블록(→ 언어 태그가 붙은 예제), 표(→ 레퍼런스 데이터)
  - CEO 계획에서 정의한 스키마로 `agent-manifest.json`을 출력합니다.
  - 사람이 읽을 수 있는 요약인 `AGENT-INDEX.md`를 출력합니다.
  - 참조가 실제 파일을 가리키는지 검증합니다.
